# 1주차 질문 은행 · IDEA (사전과제 → 나 → 구체화)

**시작 말:** "1주차 메이커즈 시작하자" + 사전과제 폼 답 붙여넣기
**목표:** 사전과제 답으로 SSOT 첫 버전을 만들고, 러프한 아이디어를 "왜 · 누구 · 문제 · 해결 · 가설"까지 구체화하고, 가벼운 테스트를 한 번 한다.
**끝 조건:** `python3 _system/check.py status`에서 1주차 "완료" (필수 칸 + 주간 요약)
**시간:** 이번 주 Claude 1~2시간 + 테스트 1시간 안팎. 첫 세션(OT 현장)은 0번까지만 해도 된다. 다시 "1주차 메이커즈 시작하자"라고 하면 이어서 한다.

## 0. 사전과제 (첫 세션)
1. 방식 소개 (3줄): 한 번에 한 질문 / 고르거나 직접 쓰기 / 답은 바로 SSOT에.
2. 사전과제 답이 메시지에 없으면 "사전과제 폼에 쓴 내 답을 붙여넣어 주세요"라고 요청한다.
3. 원문은 `weeks/week-1.md`의 "내 사전과제 답"에 그대로, 각 답은 아래 표에 따라 옮긴다. 준비 확인 답(노트북·유료 플랜·GitHub)은 옮기지 않는다.
   - 폼을 안 냈으면 폼 질문 1~4를 한 번에 하나씩 묻는다. 3번은 목적 → 고객 → 문제 → 가설 → 해결 순서로 나눠 묻는다.
4. 모임에서 나눈 이야기 중 기억에 남는 피드백이 있는지 하나 묻는다. → `records/ideas.md`
5. SSOT "지금 단계"를 "1주차"로 바꾼다.

| 폼 질문 | 옮길 곳 |
| --- | --- |
| 이름 | SSOT 맨 위 이름 |
| 1. 나를 표현하는 3가지 (단어·문장·사물 등)와 이유 | SSOT ① 한 줄 소개·가치의 재료 + `records/my-words.md` 원문. 한 줄 소개는 Claude가 초안을 보여 주고 확인받는다 |
| 2. 왜 메이커가 되어야 하나, 왜 메이커즈에 왔나 | SSOT ① 지금 상황(왜 왔나) + `records/my-words.md` 원문 (① 가치의 재료) |
| 3. 내 아이디어: 목적 / 고객 / 문제 / 가설 / 해결 | SSOT ② 왜 만드나 / 대상 / 해결하고 싶은 문제 / ③ 가설 1번 / ② 해결 방법(형태가 보이면 ② 형태도). 빈 항목은 B·C에서 묻는다. 아이디어가 아직 관심 분야뿐이면 `records/ideas.md` |
| 4. 이 아이디어를 어떻게 떠올렸나 (자주 하는 것, 가진 물건, 주변 사람, 들은 말, 전공·일, 겪은 일) | 하나씩 나눠 SSOT ① 히스토리 · 강점과 자원 · 왜 나인가에. 원문은 `records/my-words.md` |
| 5. 첫 모임 준비 (노트북, Claude·타 AI 유료 플랜, GitHub) | 옮기지 않음 |

사전과제 답은 크루가 말한 사실이므로 SSOT에 바로 옮긴다. 다만 3번은 러프한 초안이니, B·C에서 한 칸씩 다시 확인하며 다듬는다.

## A. 나 (짧고 깊게, 4~6문항)
- 사전과제 답 중 더 듣고 싶은 것을 골라 묻는다. 이미 있는 칸은 다시 묻지 않는다.
- 인생에서 방향이 바뀐 순간 하나는? 거기서 남은 것은? → 히스토리
- 남들보다 쉽게 되는 일은? (예: 사람 모으기 / 정리하고 설명하기 / 손으로 만들기) → 강점
- 지금 바로 기댈 수 있는 사람·커뮤니티·기회는? → 자원
- 일할 때 절대 포기하고 싶지 않은 것은? (예: 자유로운 시간 / 관계 / 완성도 / 재미) → 가치
- 메이커즈에 일주일에 몇 시간 쓸 수 있어요? A. 3시간 이하 B. 4~6시간 C. 7시간 이상 (기준은 5시간) → ① 지금 상황
- 나를 표현하는 말투는? A. 친근하고 가볍게 B. 차분하고 깊게 C. 유쾌하고 솔직하게 D. 직접 쓰기

## B. 아이디어 고르기
- 아이디어(1~3개)를 강점·자원과 연결한 표를 보여 준다 (연결은 "가설"). → "이 연결이 맞아요?"
- 주 5시간으로 5주 동안 해도 덜 지칠 것은? A/B/C
- 지금 가진 자원만으로 이번 주에 시작할 수 있는 것은? A/B/C
- **이걸로 할까요?** → 결정 로그 "아이디어 선정" + 이유

## C. 구체화 (한 칸씩)
- 왜 이걸 만들고 싶어요? → ② 왜 만드나
- 누구를 돕나요? 최대한 좁혀서 (예: "퇴근 후 혼자 그림 그리는 30대 직장인") → ② 대상
- 그 사람은 어떤 상황에서, 무엇이 불편한가요? → ② 문제
- 그 사람은 지금 그 불편을 어떻게 해결하고 있나요? → ② 대상
- 어떻게 해결해 주고 싶어요? → ② 해결 방법
- 형태는? 웹·앱 / SNS·콘텐츠 / 모임·커뮤니티 / 상품 / 서비스(사람이 직접) / 기타 → ② 형태
- 한 줄 설명 초안 2~3개 → 고르기 → ② 한 줄 설명
- 한 줄 소개 초안 2~3개 → 고르기 → ① 한 줄 소개

## D. 가설과 가벼운 테스트
- 가설 3개를 같이 만든다. 형식: "○○한 사람은 △△ 때문에 □□을 원할 것이다"
  1. 문제 가설: 이 사람들은 정말 이 불편을 겪는다
  2. 해결 가설: 내 방법이 그 불편을 줄인다
  3. 행동 가설: 이 사람들은 ○○(신청, 댓글, 구매)을 할 것이다
- 이번 주에 1시간 안에 할 수 있는 가벼운 테스트는? (예: 지인 3명에게 문제 질문하기 / 오픈채팅·커뮤니티에 질문 올리기 / 인스타 스토리 투표 / 비슷한 서비스 후기 10개 읽기)
- 무엇을 보면 "맞다"고 볼까? → ③ 가설 표

## E. 마무리
- 테스트를 하고 나면 "요약 만들어줘" → 주간 요약 확정 → 1주차 완료.
- 다음 모임(IDEA) 뒤에 "2주차 메이커즈 시작하자"라고 하면 된다고 안내한다.
